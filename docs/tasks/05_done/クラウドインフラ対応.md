# クラウドインフラ対応（Supabase の DB と Vercel の実行環境）

## 依頼

> Supabase 等のクラウドインフラ対応をしてしまおう。DB と Cloud コンピューティング。事前に作業工程をしらべて書き出し依頼。

## 結論

- **工程は 6 つに分かれる。** 事前の確認と判断、コードの準備、DB、Vercel、検証、運用の順に進める。
- **いちばん重いのは、ログインの扱いである。** 今まで「スコープ外」にしてきたが、クラウドに出すと URL を知っている誰でもアプリを開ける。そのまま出すと、学習記録を読み書きでき、あなたの Anthropic キーで AI を使える。最低限の守りを決めてからでないと公開できない。
- **コードにも、そのままでは載らない箇所が 5 つある。**
  - DB 名の検査
  - 応答のあとに裏で走らせている採点
  - 接続の張り方
  - AI を待つ時間
  - SQL が前提にしているローカル専用の role と表
- **DB の作り直しを先に済ませると、DB の工程が軽くなる**（`05_done/2026-10-13-architecture-refactor-db-first.md` の第 2 段）。今の 29 本の SQL を Supabase に流すより、新しい 1 本の baseline を流すほうが安全である。

ほかに確かめること:

- **RLS:** Supabase では新しい表に RLS が自動で付く。アプリは表の持ち主の role で直接つなぐので、RLS の規則が無くても読み書きできるはずである。ただし、どの role でつなぐかによって変わる。実際に 1 行書いて確かめる。
- **時刻:** Vercel のサーバーは UTC で動く。`plan.mjs` は +9 時間を手で足し、SQL は `'Asia/Tokyo'` を使っているので、「今日」は変わらないはずである。検証で今日の計画の日付を確かめる。
- **教材の反映:** `npm run data:sync` は `db.mjs` を使うので、C1 を直すまで Supabase に向けられない。

## 工程

### 工程 0: 事前の確認と判断（コードを触る前）

1. **Supabase の課金と上限を確かめる。** メモには「無料組織は使用上限を超え、grace period は終わっている」とある。この状態では、リクエストが止められることがある。ダッシュボードの Billing / Usage を見て、`speak-kit` のプロジェクトで書き込みができるかを確かめる。
2. **リージョンを決める。** 今は Supabase がムンバイで、Vercel の関数は既定でアメリカ東部（`iad1`）で動く。1 回の操作で SQL を何本も投げるので、DB と関数が離れていると遅くなる。
   - 案 A: Vercel の関数をムンバイ（`bom1`）に置く。
   - 案 B: Supabase を東京で作り直し、Vercel の関数を東京（`hnd1`）に置く。日本から使うならこちらが速い。中身が空なので、作り直しの損は無い。
3. **公開したときの守りを決める。**
   - 案 A: Supabase Auth でログインを作る。メモの方針どおりだが、作業が一番大きい。全表に学習者の区別が要る（リファクタリング案の D-5）。
   - 案 B: 合言葉 1 つで守る。Next.js の middleware で Basic 認証をかけ、合言葉は Vercel の環境変数に置く。一人で使う間はこれで足りる。
   - 案 C: Vercel の Deployment Protection（Password Protection は有料プラン）。
4. **ローカルの学習記録を持っていくか決める。** 今のローカルには、テストが書いた偽の回答が混ざっている（`02_backlog/2026-10-13-isolate-test-database.md`）。持っていかず、クラウドは教材だけで始めるのが簡単である。
5. **作業の順序を決める。** 次のタスクとの前後関係を決める。
   - `02_backlog/2026-10-13-commit-and-push.md`: Vercel は GitHub から取ってくるので、こちらが先に要る。
   - `02_backlog/2026-10-13-isolate-test-database.md`
   - リファクタリング案の第 2 段（DB の作り直し）

1. C1: `DATA_BACKEND` と、接続先ごとの DB 名の検査。設定画面の「保存先」に実際の値を出す。
2. C2: 接続プーラー向けの `Pool` の設定。
3. C3: 裏の採点を `after()` にする。

5. 工程 0-3 で決めた守り。案 B なら `src/middleware.ts` に Basic 認証を置き、合言葉が未設定なら起動を止める。

### 工程 2: DB（Supabase）

1. `npx supabase link --project-ref <ref>`（パスワードは `env/secret.yaml` から渡し、コマンドの履歴やログに残さない）。
2. schema を流す。第 2 段の baseline があればそれを、無ければ 29 本と、前提の role・表を流す。
3. RLS と権限を確かめる。アプリが使う接続文字列（プーラー経由）で、1 行 SELECT と INSERT を試す。Data API には、どの表も公開しない。
4. `DATA_BACKEND=supabase npm run data:sync -- --apply` で教材を入れる。件数をローカルと突き合わせる（表現 51、練習問題 325、クイズ 257、混同ペア 34）。
5. 工程 0-4 で持っていくと決めた場合だけ、学習記録を移す。

### 工程 3: 実行環境（Vercel）

1. `npx vercel link` で新しいプロジェクト `speak-kit` を作る。既存の `vercel-nextjs-starter` には載せない。
2. GitHub の `kurosawa-kuro/speak-kit` をつなぐ。`main` への push で本番、ほかのブランチでプレビューが作られる。
3. 環境変数を Vercel に入れる（`npx vercel env add`）。値はコミットしない。Doppler の `apps/dev` を丸ごと入れない。
4. 関数のリージョンを、工程 0-2 で決めた場所にする（`vercel.json` の `regions`）。
5. まずプレビューにデプロイし、工程 4 の検証を通してから本番にする。

### 工程 4: 検証（プレビューの URL で）

`docs/08_release_runbook.md` の Golden Path をクラウドで通す。

1. 守りが効いていること。合言葉なし・ログインなしでは、画面も `/api/*` も開けない。
2. AI をオフ（設定画面）にした状態で、今日 → クイズ → 回答 → 記録が通る。Supabase に行が増える。
3. AI をオンにして、記述の採点と会話が動く。裏の採点（C3）が最後まで終わる。
4. 1 回の操作の応答時間を、ローカルと比べる（今日の計画、記録）。遅すぎる場合はリージョンを見直す。
5. 「今日」の日付と週の区切りが、日本時間で合っている。
6. Vercel の関数のログに、接続数の上限や実行時間切れのエラーが出ていない。

### 工程 5: 運用

1. バックアップ: Supabase の無料プランで取れるバックアップの範囲を確かめる。足りなければ、`pg_dump` を定期的に取る方法を決める。
2. 戻し方: Vercel は前のデプロイに戻せる（Instant Rollback）。DB の schema を変えるときの戻し方を runbook に書く。
3. `docs/08_release_runbook.md` に、デプロイ・検証・戻し方の手順を実際のコマンドで書く。
4. 配布（知人が自分のアカウントで立てる「Deploy with Vercel」ボタンとテンプレート化）は、自分の分が安定してからの別タスクにする。

## Risk

- **組織の上限:** Supabase の組織が上限を超えたままだと、デプロイしても DB へのリクエストが止まる。工程 0-1 で確かめるまで進めない。
- **AI キーの課金:** 守りが無いまま公開すると、URL を知った他人があなたの Anthropic キーで課金させられる。工程 1-5 を省かない。
- **DB の接続数:** 接続プーラーを使わないと、Vercel の関数が増えたときに Supabase の接続数の上限に届き、全部の画面がエラーになる。
- **途中で切れる書き込み:** AI の待ち時間が関数の上限を超えると、書き込みの途中で切れる。トランザクションに入っていない書き込み（リファクタリング案の B2）が中途半端に残る。

## Owner-only Decisions

- 工程 0-1: Supabase の課金と上限への対応（有料にする、別の組織に移す、など）
- 工程 0-2: リージョン（ムンバイのまま Vercel を合わせるか、東京で Supabase を作り直すか）
- 工程 0-3: 公開したときの守り（Supabase Auth、合言葉、Vercel の保護）

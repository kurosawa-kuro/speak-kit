# 実運用可能な状況かのレビュー（ローカルで一人が毎日使う前提）

## 依頼

> 実運用可能な状況かをレビュー依頼。cloud、ログインは一旦スコープ外。問題、課題があれば書き出し。

## 結論

**まだ実運用には出せない。** アプリ自体は動く（テスト 21 件が全件成功、本番ビルドが成功、主要 API は 1 秒以内に応答）。ただし、毎日の学習記録を預けるには次の 6 つが足りない。

1. 学習記録のバックアップが一つも無い
2. `npm test` が本物の学習記録に偽の回答を書き込む
3. 同じ Wi-Fi の誰でも、認証なしでアプリを開け、あなたの Anthropic キーで AI を使える
4. Mac を再起動すると Postgres が起動せず、アプリの起動手順もどこにも書かれていない
5. 教材の正本（`data/`）と直近の変更がコミットされていない
6. 会話画面で、日本語入力の変換を確定する Enter で送信されてしまう

この 6 つを直せば「一人で毎日使う」段階に入れる。設計の問題（`2026-10-13-architecture-refactor-db-first.md`）は、使いながら直せる。

## 運用を止める問題（直してから使い始める）

### R1. バックアップが無い

- 学習記録の置き場は、ローカル Postgres の `speak_kit` だけである。
- `pg_dump` の定期実行も、cron も launchd の設定も無い。
- Time Machine の保存先が設定されていない（`tmutil destinationinfo` の結果: `No destinations configured`）。
- ディスクの故障や DB の操作ミスで、学習記録がすべて消える。

**対策:**

- 1 日 1 回 `pg_dump -Fc speak_kit` を取る launchd ジョブを置く。
- 保存先は repo の外のディレクトリにし、7 日分残す。
- 戻す手順（`pg_restore`）を `docs/runbooks/` に書き、一度実際に戻してみる。

### R2. テストが本物の学習記録を汚す

- `src/test/golden-path.test.mjs` と `src/test/settings.test.mjs` は、本物の `speak_kit` に向けて `dispatch` を呼んでいる。
- 1 回の `npm test` で書き込まれるもの: クイズの回答、記述の回答、会話の開始・送信・終了、混同ペアの登録（lend / borrow）。
- 回答時間 12 ミリ秒のクイズ回答（テストが書く値）が、既に 16 件ある（13:28〜18:55）。今日のレビューで流したテストの分も含む。
- この偽の回答は、正答率・反応時間・弱点の診断・今日の計画に混ざる。

**対策:**

- テストは使い捨ての DB（例: `speak_kit_test`）に向ける。テストの最初に schema と教材を入れる。
- `src/lib/db.mjs` の検査に、テスト用の DB 名を許す分岐を足す。
- 既に入った偽の行は、判別できる分だけ消すか、試用データとして DB ごと作り直す。作り直すかどうかは、リファクタリング案の第 2 段と一緒に owner が決める。

### R3. Wi-Fi の誰でも使える

- 開発サーバーは全インターフェース（`*:3000`）で待ち受けている。LAN の IP（`http://192.168.0.226:3000/api/ai/status`）から 200 が返った。
- 認証が無いので、同じネットワークの誰でも次のことができる。
  - 学習記録の読み書き
  - 設定の変更（`POST /api/settings`）
  - あなたの Anthropic キーで AI を呼ぶ（`/api/ai/talk` ほか）。課金があなたに付く。
- カフェなどの公衆 Wi-Fi で使うと、その場の全員に開くことになる。

**対策:**

- 起動を `next dev -H 127.0.0.1 -p 3000` に変え、自分の Mac からしか開けないようにする（ログインはスコープ外なので、待ち受け先で守る）。
- 画面から使われていない `/api/ai/talk`、`/feedback`、`/scenario`、`/grade` を消す。

### R4. 再起動すると動かない、起動のしかたが書かれていない

- **Postgres が自動起動しない。** Homebrew の `postgresql@16` はサービスとして登録されていない（`brew services list` の結果が `none`）。Mac を再起動すると DB が上がらず、アプリはすべての画面でエラーになる。
- **アプリの起動コマンドがどこにも書かれていない。** 今日動いていた起動コマンドは次のとおりだった。

  ```sh
  doppler run -p apps -c dev --only-secrets AI_ANTHROPIC_API_KEY -- sh -c 'export ANTHROPIC_API_KEY="$AI_ANTHROPIC_API_KEY"; unset AI_ANTHROPIC_API_KEY; exec npm run dev'
  ```

  このコマンドは README にも runbook にも無い。
- **`Makefile` が初期状態のまま。** `make setup`、`make dev`、`make test` はすべて `TODO` と出すだけで、何もしない。
- **README が古い。** 「アプリ本体は未着手」「`make dev`（現状は TODO）」と書かれている。

**対策:**

- `brew services start postgresql@16` で自動起動にする。
- `make dev`（上の起動コマンドを `-H 127.0.0.1` 付きで）、`make test`、`make backup`、`make restore` を実装する。
- README の「いまのディレクトリ」と起動手順を、今の実態に書き直す。

### R5. 変更がコミットされていない

- 未コミットの変更が 29 ファイル（+393 / −91 行）ある。
- `data/`（教材の正本の YAML）は git に一度も入っていない。
- `main` は `origin/main` より 4 コミット先にあり、GitHub に送られていない。コミットメッセージはすべて `wip` である。
- 教材の正本は YAML なので、`data/` を消すと教材を戻せない（DB から `data:export` で書き出し直すことはできる）。

**対策:**

- 変更を意味のある単位でコミットし、push する。
- `data/` を含める。

### R6. 日本語入力の Enter で送信される

- `src/app/screens/talk.js:203` は `e.key === "Enter"` だけを見て送信している。日本語入力の変換を確定する Enter でも送られる。
- 会話の途中で日本語を混ぜると、書きかけで送られる。
- 会話の記録と「言えなかった場面」の判定が、書きかけの文で作られる。

**対策:** `e.nativeEvent.isComposing` が true のときは送信しない。クイズの Enter（`src/app/screens/quiz.js:96`）も同じように確かめる。

## 後回しでよいもの

- **DB の作り直しの必要:** migration の適用記録が無く、28 本を流し直すと 22 本目で失敗する。空の DB には、手作業なしでは乗らない。DB を作り直す時（リファクタリング案の第 2 段）に解決する。
- **`pg` の警告:** `data:sync` で、`pgpass` の扱いがいずれ無くなるという警告が出る（`DeprecationWarning`）。動作には影響しない。
- **日本時間の固定:** 日本時間と月曜始まりが固定されている。一人で日本で使う限り問題ない。

## 今日のレビューで起きたこと

- 本番ビルドを、動いていた開発サーバーと同じ `.next` に出したため、開発サーバーが 500 を返すようになった。`.next` を消し、元と同じコマンド（R4）で起動し直した。そのあと、ページ、AI の状態、主要 API 4 本が正常に応答することを確かめた。
- `npm test` と API の確認で、本物の `speak_kit` に次の行が増えた。
  - クイズの回答・会話・記述の回答（テスト 1 回分）
  - 練習問題の作成 1 件
  - これは R2 の問題そのものである。

## 推奨する順序

1. R5: コミットと push。今の状態を失わないようにする。
2. R1: バックアップを置き、一度戻してみる。
3. R3・R4: 自分の Mac でだけ開くようにし、起動とテストを `make` にまとめ、Postgres を自動起動にする。
4. R2: テスト用の DB に分ける。
5. R6・H1・H5: 会話画面の小さな修正。
6. 残りは、リファクタリング案の段階計画の中で直す。

## Owner-only Decisions

- R2 で既に入った偽の回答を、消すか、DB の作り直しで捨てるか
- バックアップの保存先（外付けディスク、iCloud Drive、別の Mac など）
- R3 で、スマホなど別の端末からも使いたいか。使いたいなら、待ち受けを自分の Mac に絞る代わりに、合言葉などの最小限の守りが要る（ログインは今回のスコープ外）

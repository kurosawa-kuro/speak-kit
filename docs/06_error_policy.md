# 06 エラー方針

出典はアイディアノートの「AI 機能の安全設計」。対象は、speak-kit の API Routes と UI である。RPC の入口（`src/app/api/[name]/route.js`）は、入力の誤りを 400、見つからないものを 404、想定外の例外を 500 で返し、500 は `logs/server-errors.log` に 1 行残す。

## エラー分類

コアの失敗と AI の失敗は別の分類である。AI の失敗をコアの応答へ混ぜない。

| 分類 | 意味 | 対応 |
|---|---|---|
| キー未設定 | `ANTHROPIC_API_KEY` が無い。デプロイ直後、または AI を使わない人 | 起動時に判定し、AI 機能全体を disabled。案内文を出す。コアは通す |
| キー無効（401 系） | 入力ミス、停止、失効 | その AI 呼び出しだけを失敗にする。コアへ伝播させない |
| レート制限 / 一時エラー（429 / 5xx） | 無料枠超過、Anthropic 側の障害 | リトライは任意。失敗してもコアのコードパスを汚染しない |
| 到達不可 | 一時的な通信障害 | AI 呼び出しの timeout が、コア機能のレスポンスを巻き込まない |
| コアの失敗 | テキストのフレーズ練習、学習記録そのものの失敗 | AI の Error Boundary の外で扱う。AI の disabled 表示で隠さない |

- AI 呼び出しは常に try/catch。失敗時は構造化エラーを返すだけで、プロセスやリクエストを落とさない。
- UI 側は Error Boundary で AI セクションを囲む。AI 側がクラッシュしても、コア機能の画面は正常表示を保つ。粒度は未決。
- 有効なキーで稼働中のセッションからキーを無効な値に変えても、コア側の操作はエラーにしない。

## ログ

- 秘密情報をログに出さない。API キー、Doppler の値、Supabase の資格情報をログとドキュメントに書かない。
- クライアントへ返すのは `aiEnabled: boolean` と、AI 失敗時の構造化エラーである。キーの有無の判定材料を返さない。
